# Kimi Code support in the manifest sync harness

Date: 2026-07-17
Status: approved design, pre-implementation

## Problem

qol-skills ships a Claude Code marketplace (`.claude-plugin/marketplace.json`) and a Codex
marketplace (`.agents/plugins/marketplace.json`), both generated by
`scripts/sync-plugin-manifests.cjs` from per-plugin manifests. Kimi Code cannot consume the
repo: it requires its own per-plugin manifest (`kimi.plugin.json` or
`.kimi-plugin/plugin.json`) and its own marketplace catalog format, neither of which exists.

## Approach

Kimi is a **derived third target** in the existing sync script — the same pattern Codex
already uses. Base metadata (`name`, `description`, `version`, `author`) keeps resolving
two-way between the Claude and Codex manifests (including the git changed-file provenance
conflict logic, which stays untouched). The Kimi manifest is always regenerated from that
base; it is never a provenance source and must not be hand-edited for shared fields.
Kimi-specific extras in an existing Kimi manifest are preserved across re-syncs, exactly how
Codex extras (`interface`, `mcpServers`, `apps`) are preserved today.

Rejected alternatives: full three-way metadata sync (complexity without payoff) and a
separate generator script (duplicates base resolution, drifts).

## Generated files

### Per plugin: `plugins/<name>/.kimi-plugin/plugin.json`

Generated for every directory under `plugins/`:

```json
{
  "name": "<plugin>",
  "version": "<from base>",
  "description": "<from base>",
  "author": { "name": "KMRH47" },
  "skills": "./skills/",
  "interface": { "displayName": "...", "...": "..." },
  "hooks": [ { "event": "PreToolUse", "matcher": "Bash", "command": "node bin/x.cjs" } ]
}
```

Field rules:

- `name` / `version` / `description` / `author`: from the resolved base.
- `skills`: `"./skills/"` when the plugin has a `skills/` directory (all current plugins do).
- `interface`: copied from the Codex manifest's `interface` when the Kimi manifest does not
  define one, restricted to the subfields Kimi documents (`displayName`, `shortDescription`,
  `longDescription`, `developerName`, `websiteURL`) so `/plugins` shows no diagnostics. A
  hand-written Kimi `interface` wins over the Codex-derived one. When neither manifest
  defines an `interface`, the field is omitted.
- `hooks`: translated from `hooks/hooks.json` when present (see Hook translation).
- Kimi-only extras (`sessionStart`, `skillInstructions`, `commands`, `keywords`,
  `homepage`, `license`, `mcpServers`): preserved verbatim from an existing Kimi manifest;
  never invented by the sync.

The `.kimi-plugin/plugin.json` location (not root `kimi.plugin.json`) matches the installed
superpowers plugin and stays symmetric with `.claude-plugin/` and `.codex-plugin/`.

### Repo root: `.kimi-plugin/marketplace.json`

Kimi's custom marketplace catalog format:

```json
{
  "version": "2",
  "plugins": [
    { "id": "<name>", "displayName": "<displayName or name>", "source": "./plugins/<name>" }
  ]
}
```

- Entry order follows the Claude marketplace order (same `existingOrder` reuse as the Codex
  marketplace sync).
- `displayName` comes from the plugin's Codex `interface.displayName` when available,
  otherwise the plugin name. Any other hand-added entry extras are preserved.

## Sync script changes (`scripts/sync-plugin-manifests.cjs`)

- `manifestPaths()` gains `kimi: <pluginRoot>/.kimi-plugin/plugin.json`.
- `syncPlugin()` additionally reads the Kimi manifest, validates its `name` matches the
  directory (same failure style as Claude/Codex), generates the next manifest via a new
  `kimiManifest(root, pluginName, base, existingKimi, codexManifest)`, and writes it through
  the existing `writeJson` (so `--check` and change reporting work unchanged).
- New `syncKimiMarketplace()` mirroring `syncCodexMarketplace()`: default document
  `{ "version": "2", "plugins": [] }`, preserves entry order and hand-added extras.
- JSON output formatting (2-space indent, non-ASCII escaped, trailing newline) is unchanged —
  `jsonText` is reused.

## Hook translation

Input: `plugins/<name>/hooks/hooks.json` (Claude format, shared with Codex today):

```json
{ "hooks": { "<Event>": [ { "matcher": "...", "hooks": [ { "type": "command", "command": "..." } ] } ] } }
```

Output: inline `hooks` array in the Kimi manifest:

```json
"hooks": [ { "event": "<Event>", "matcher": "...", "command": "node <relpath>" } ]
```

Rules:

- One Kimi rule per command hook, in file order; `matcher` copied when present; `timeout`
  omitted (Kimi's 30s default applies).
- Command rewrite: every current hook command is the same wrapper shape,
  `node -e '<plugin-root-resolver>' <pluginName> <relpath>`. The wrapper exists only because
  Claude/Codex give hooks no reliable working directory. Kimi runs plugin hooks with
  **cwd = plugin root** (and sets `KIMI_PLUGIN_ROOT`), so the translated command is simply
  `node <relpath>`, with `<relpath>` extracted as the wrapper's final argument.
- A command that does not match the wrapper shape passes through verbatim (escape hatch).
- A malformed `hooks.json` (unparseable, or not the expected object shape) fails the sync
  loudly with the file path — hooks must never be silently dropped.
- Payload compatibility: Kimi's stdin payload uses the same `tool_input.command` shape the
  bin scripts already parse. During implementation, audit `plugins/*/bin/*.cjs` for
  `CLAUDE_*`-only environment reads (e.g. `CLAUDE_PLUGIN_ROOT`, `CLAUDE_PROJECT_DIR`) and
  make minimal compatibility fixes (honor `KIMI_PLUGIN_ROOT` alongside). Hook behavior
  itself is out of scope.

## CI (`.github/workflows/sync-plugin-manifests.yml`)

- Trigger paths: add `.kimi-plugin/marketplace.json`.
- Validation snippet: extend to check that each Kimi marketplace entry's `id` matches the
  `name` in its plugin's `.kimi-plugin/plugin.json`, the same way it does for Claude and
  Codex.
- Auto-commit `git add` list: add `.kimi-plugin/marketplace.json`.

## Tests (`test/sync-plugin-manifests.test.cjs`)

Extend the temp-repo fixtures to cover:

- Kimi manifest generation from base (shared fields, `skills` path).
- Preservation of Kimi-only extras (`sessionStart`, `skillInstructions`, `commands`) across
  re-sync.
- `interface` inherited from Codex when no Kimi manifest exists; existing Kimi `interface`
  wins.
- Hook translation: wrapper command → `node bin/x.cjs`, `matcher` preserved, event order
  preserved; non-wrapper command passes through verbatim; malformed `hooks.json` fails.
- Kimi marketplace generation, entry order preservation, and extra preservation.
- Kimi manifest name-mismatch failure.
- `--check` reports Kimi drift without writing.

## Error handling

- Kimi manifest `name` mismatch with its directory: hard failure, same message style as the
  existing Claude/Codex validation.
- Malformed `hooks.json`: hard failure naming the file.
- Non-wrapper hook command: verbatim passthrough, no failure.

## Out of scope

- Kimi slash commands (`commands/` — no plugin ships command files today; the field is
  preserved if hand-added later).
- Porting Claude `agents/` directories to Kimi subagents.
- Three-way metadata conflict resolution.
- Changing any hook's behavior.
